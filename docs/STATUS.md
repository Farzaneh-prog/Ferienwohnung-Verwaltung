# وضعیت پروژه — سند انتقال (۲۰۲۶-۰۹-۱۶)

این فایل برای شروع یک مکالمه جدید نوشته شده — خلاصه‌ی دقیق «الان کجاییم»، بدون نیاز
به مرور تاریخچه طولانی مکالمه قبلی. اسناد اصلی (`سند-معماری-سیستم-مهمانخانه.md` و
`نظافتچی_ها-و-فرمول_های-مالی.md`) هنوز روی دیسک هستن و باید دوباره خونده بشن — این
فایل جایگزینشون نیست، فقط می‌گه واقعیت پیاده‌سازی‌شده کجاها با اون اسناد فرق کرده.

---

## ۱. تفاوت‌های اساسی بین فرض اولیه و واقعیت

| فرض سند اولیه | واقعیت پیاده‌سازی‌شده |
|---|---|
| یک فایل `reservations.xlsx` با ۲ شیت | **دو فایل جدا**: `GästeListe_2026K.xlsx` (Karlstraße) و `GästeListe_2026_Pf.xlsx` (Eisenach) |
| هر فایل = یک شیت به‌ازای هر ملک | هر فایل = **۴ شیت فصلی (`1`-`4`) + شیت `Muster`** |
| `Muster` = شیت الگو/نمونه (نادیده گرفته می‌شد) | `Muster` واقعاً **محل نگه‌داری رزروهای سالی که هنوز فایل خودش را ندارد** (مثلاً بوکینگ ۲۰۲۷ که توی فایل ۲۰۲۶ نگه داشته می‌شه) — باید مثل بقیه شیت‌ها خونده/نوشته بشه |
| Cowork مستقیم و خودکار Airbnb/Booking رو می‌خونه | **متوقف شد** — Airbnb و Booking.com هر دو در شرایط استفاده‌شون صریحاً دسترسی خودکار/AI رو ممنوع کردن (حتی به اکانت خود کاربر)، با ریسک مسدودی اکانت. جایگزین شد با **آپلود دستی export رسمی** |
| — | فایل‌های واقعی ۲۸-۴۰ مگابایت بودن (فرمت‌بندی خالی روی ~۱ میلیون ردیف) — با `tools/shrink_xlsx.py` به زیر ۲۰۰KB رسوندیم |

## ۳. مسیر داده — چطور یک رزرو وارد فایل می‌شود

۱. شما از Booking.com Extranet یا Airbnb Host، export رسمی می‌گیرید (نه Cowork، نه اسکرپینگ)
۲. `/import` → آپلود → `import_parser.py` تشخیص می‌ده فرمت کدومه و پارس می‌کنه
۳. اگه یه کد رزرو توی چند فایل باشه، `merge_reservation_entries` فیلد به فیلد **ترکیب** می‌کنه (نه فقط یکی رو انتخاب) — چون AA و AX به داده‌ی هم‌زمان از هر دو فایل بوکینگ نیاز دارن
۴. پیش‌نمایش (جدید/تکراری/کنسلی) → تأیید → `xlsx_writer.process_batch`
۵. `append_reservation`: ردیف جدید **فقط به یه ردیف خالی/انتهای شیت درست اضافه می‌شه**، هیچ‌وقت وسط شیت درج نمی‌شه (چون openpyxl هنگام درج/حذف ردیف، فرمول ردیف‌های دیگه رو خودکار اصلاح نمی‌کنه — بر خلاف خود اکسل)
۶. فرمول‌ها یا از یه ردیف مجاور «کپی» می‌شن (`clone_formulas`) یا برای ستون‌های حساس، **صریح نوشته می‌شن** (`EXPLICIT_FORMULAS`/`EXPLICIT_LITERALS`) — بخش ۵ رو ببینید
۷. کنسلی → هیچ‌وقت حذف نمی‌شه، فقط ستون `Storniert` (BB) = `ja` می‌شه (چون حذف فیزیکی هم همون مشکل فرمول رو داره)

## ۴. چیزی که هیچ export ای نمی‌ده — همیشه دستی

- **اسم مهمان و ایمیل**: هیچ‌کدوم از سه فرمت export (نه Booking ساده، نه مفصل، نه Airbnb) این رو نمی‌ده. همیشه placeholder (`Gast (Code XXXX)`) می‌مونه تا از `/complete` پر بشه
- **تعداد بزرگسال/کودک**: فقط توی Booking «مفصل» هست؛ Booking «ساده» و Airbnb ندارن
- **`/complete` فعلاً فقط ۴ فیلد داره**: اسم، ایمیل، بزرگسال، کودک — چیزهای دیگه‌ای که ممکنه لازم بشه (مثلاً اگه یه فیلد مالی از یه پلتفرم خاص نیومد) هنوز اضافه نشده؛ باید لیست دقیق «کدوم فیلد از کدوم پلتفرم میاد/نمیاد» کامل بشه و فرم بر همون اساس تکمیل بشه

## ۵. وضعیت دقیق هر ستون فرمولی (مهم‌ترین بخش برای بازبینی)

### ✅ صریحاً توسط شما تأیید و کد شده (`xlsx_writer.py`)
| ستون | فرمول/مقدار | منبع |
|---|---|---|
| I, J | `=F*G`, `=H*F` | ساختاری |
| M (Übernachtungssteuer) | `=G*F` | تأیید مستقیم |
| O (Gezahlt) | `=Preis+M` (Preis از export) | تأیید مستقیم |
| P (Putzarbeit) | Booking: نرخ ثابت ۵۰(Karlstraße)/۶۵(Eisenach) — Airbnb: `Reinigungsgebühr` واقعی | تأیید مستقیم |
| Z (Umsatzsteuersatz) | همیشه `0.19` | تأیید مستقیم |
| AA (Nettobetrag) | `Commission amount` از Booking «مفصل» — **فقط Booking**، Airbnb نگاشته نشده | تأیید مستقیم |
| AF (Endreinigung) | `=IF(R="ja",P,P/1.07)` — همه پلتفرم‌ها | تأیید مستقیم |
| AG (Stellplatz) | همیشه `0` | تأیید مستقیم |
| AK | `=IF(AQ="ja",AJ,AJ/1.07)` | تأیید مستقیم |
| AL | `=AK*1.07` | تأیید مستقیم |
| AM | `=AJ` | تأیید مستقیم |
| AV (متن پیام پرداخت) | فرمول کامل ۴حالته (Airbnb/booking/پرداخت‌شده/Vrbo) | تأیید مستقیم |
| AX (Payment Charge von Booking) | `Commission(ساده) − AA` — **فقط Booking** | تأیید مستقیم |
| BC (چک‌سام) | `=AF+AH+AN+AO+AP-AE+AG` | تأیید مستقیم |
| S | placeholder `0` | تأیید مستقیم (موقت، بعداً واقعی) |
| T | placeholder `3.5` | تأیید مستقیم (موقت) |
| U | `=T*12` | تأیید مستقیم |
| V | placeholder `"M-Ü"` | تأیید مستقیم (موقت) |

### ⚠️ فقط «کپی از ردیف مجاور» — هنوز صریحاً تأیید نشده
ستون‌های `Q، AB، AC، AE، AH، AI، AJ، AN، AO، AP، AR، AS، AT، AU، BE` — الگوشون توی
۳ ردیف نمونه‌ی واقعی که بررسی کردیم یکسان بود، ولی برخلاف لیست بالا، **شما مستقیم
تأییدشون نکردید**. ریسک: اگه یه ردیف قدیمی‌تر که به‌عنوان «نمونه» انتخاب می‌شه
فرمول قدیمی/ناقص داشته باشه (دقیقاً همون مشکلی که با BC و AV پیش اومد)، ممکنه
دوباره تکرار بشه.

### ❌ همیشه خالی می‌مونه — تصمیم دستی/کسب‌وکاریه
`K (Private Zweck)، L (Arbeitszweck)، R (Ausländische Firma)، W (Fahrtkosten)،
X (Rechnungsnummer)، AD (Adresse)، AQ (Ausländische Firma - همون هدر تکراری)،
AW (bereits überwiesen)، AY (Paypal)، AZ (رزرو برای فلگ مالیات، فاز بعد)`

## ۶. کشف‌های فنی مهم (برای جلوگیری از تکرار اشتباه)

1. **`ws.cell(row, col, value=None)` در openpyxl هیچ کاری نمی‌کنه** (چون `None`
   سنتینل «مقداری داده نشده»ست) — همیشه `cell.value = None` مستقیم.
2. ستون‌های `R` و `AQ` **دقیقاً همون متن هدر** رو دارن (`Ausländische Firma mit
   steuer in Heimat`) — نگاشت بر اساس اسم هدر نمی‌تونه بینشون فرق بذاره؛ برای همین
   فرمول‌های `EXPLICIT_FORMULAS` مستقیم با حرف ستون (نه اسم فیلد) آدرس‌دهی می‌شن.
3. برخی ردیف‌های قدیمی، فرمول رو به‌صورت **متن/عدد چسبونده‌شده** دارن نه فرمول زنده
   (مثلاً `AV` گاهی متن ثابت بود، `BC` نسخه‌ی قدیمی/ناقص فرمول رو داشت) — یعنی
   «کپی از ردیف مجاور» به‌تنهایی قابل‌اعتماد نیست.
4. ردیف‌های خالی وسط شیت (از پاک‌کردن دستی قبلی با Delete، نه حذف کامل ردیف) به‌عنوان
   «جای خالی قابل‌استفاده» در نظر گرفته می‌شن — ردیف جدید می‌تونه توی یه شکاف وسط
   شیت بیفته، نه لزوماً انتهای فیزیکی؛ این عمدیه (امن‌تر از همیشه انتهای شیت).

## ۷. زیرساخت Cowork/WordPress — بلااستفاده فعلاً

`wordpress-plugin/marktresidenz-incoming-api.php` (نصب‌شده روی
marktresidenz-eisenach.de) و `tools/apply_incoming.py` برای مسیر «Cowork مستقیم
Airbnb/Booking رو می‌خونه» ساخته شده بودن. چون اون مسیر به‌خاطر ToS متوقف شد،
این زیرساخت الان **بلااستفاده‌ست** ولی حذف نشده — می‌تونه برای چیز دیگه‌ای
(مثلاً دریافت هشدار نظافتچی از راه دور) دوباره استفاده بشه، یا اگه تصمیم گرفتید
کلاً لازم نیست، می‌شه پاکش کرد.

## ۸. سؤالات باز که باید در بازبینی جواب داده بشن

1. **رزروهای کنسل‌شده‌ی قدیمی** که از قبل توی فایل هستن (نه از export جدید) —
   چطور شناسایی/پرچم بشن؟ راه خودکار نداریم.
2. **کنسلی Airbnb** — export ایربنب اصلاً ستون وضعیت نداره؛ راه‌حل جایگزین لازمه.
3. **`/complete` باید چه فیلدهایی داشته باشه** — لیست دقیق «چی از کجا میاد/نمیاد».
4. **ستون‌های فقط-کپی‌شده (بخش ۵)** — باید یکی‌یکی مثل بقیه صریح تأیید بشن یا نه؟
5. **مرتب‌سازی فیزیکی ردیف‌ها** — عمداً انجام نمی‌شه (ریسک فرمول)؛ اگه واقعاً لازمه،
   باید یه ابزار جدا و محتاط برای بازسازی دوره‌ای کل شیت طراحی بشه.
6. **آینده‌ی Cowork/WordPress** — نگه داریم یا پاک کنیم؟
7. **فازهای بعدی طبق سند اصلی** (ایمیل خودکار مهمان، واتساپ نظافتچی، انتشار
   گیت‌هاب نهایی) — اولویت‌بندی مجدد لازمه با توجه به تغییر مسیر فاز ۲.
