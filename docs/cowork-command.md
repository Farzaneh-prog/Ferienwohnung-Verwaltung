# فرمان روزانه Cowork — استخراج رزرو

این فایل فرمانی است که باید به Cowork داده شود (به‌عنوان دستور استاندارد/زمان‌بندی‌شده روزانه).
هر تغییری در این فرمان، این فایل رو هم به‌روز نگه دار.

---

## فرمان

```
هر روز صبح ساعت ۸ (به‌وقت آلمان)، این کار رو انجام بده:

۱. وارد داشبورد Airbnb، اکسترانت Booking.com و داشبورد Vrbo شو (با همون
   حساب‌هایی که از قبل روی این کامپیوتر لاگین هستن).

۲. تعیین بازه‌ی زمانی:
   - اگه توی این درخواست یه تاریخ مشخص بهت داده شد (مثلاً «از تاریخ ۲۰۲۶-۰۸-۰۱
     بخون»)، از همون تاریخ به بعد رو چک کن.
   - در غیر این صورت (حالت روزانه‌ی خودکار پیش‌فرض)، فقط رزروهایی که از دیروز
     به بعد ثبت شدن (تاریخ خودِ بوک‌شدن، نه تاریخ ورود مهمان) رو چک کن.

۳. برای هر دو ملک — Marktresidenz Karlstraße و Marktresidenz Eisenach —
   لیست رزروها رو چک کن:

   الف) رزروهای جدید: هر رزروی که توی بازه‌ی بالا ثبت شده. برای هرکدوم، **هر
        اطلاعاتی که روی صفحه‌ی جزئیات اون رزرو (Airbnb/Booking/Vrbo) می‌بینی رو
        بگیر** — نه فقط یه لیست ثابت. مخصوصاً این موارد اگه دیدی حتماً بگیر:

        شناسایی/اقامت:
        - property: "karlstrasse" یا "eisenach"
        - platform: "Airbnb" یا "booking" یا "Vrbo"
        - guest_name: اسم کامل مهمان
        - guest_email: ایمیل مهمان (اگه پلتفرم نشون بده — حتی ایمیل واسط
          Airbnb مثل xxx@guest.airbnb.com هم قبوله)
        - checkin / checkout: فرمت YYYY-MM-DD
        - adults / children: تعداد بزرگسال و کودک زیر ۱۸ سال
        - confirmation_code: کد تأیید/رزرو پلتفرم

        مالی (هرچی از صفحه رزرو/payout قابل‌دیدنه — سخت‌گیر نباش، اگه یه رقمی
        رو دیدی ولی مطمئن نیستی دقیقاً چیه، همون‌جوری با یه برچسب توضیحی توی
        extra بذار، حدس نزن که کدوم ستونه):
        - paid_amount: کل مبلغی که مهمان پرداخت کرده/می‌کنه
        - cleaning_fee_charged: هزینه نظافت که از مهمان گرفته شده (اگه پلتفرم
          جدا نشونش بده)
        - platform_commission: کمیسیون/کارمزد پلتفرم (از صفحه payout/earnings)
        - tax_amount: هر مالیاتی که خودِ پلتفرم جمع/نشون داده
        - payout_amount: مبلغی که واقعاً به حساب می‌رسه بعد از کسر کارمزد
        - address: آدرس مهمان (اگه جایی نشون داده شده، مثلاً برای فاکتور)
        - extra: هر چیز دیگه‌ای که توی صفحه رزرو دیدی و فکر می‌کنی ممکنه مهم
          باشه ولی توی لیست بالا نبود — به‌صورت {"برچسبی که خودت دیدی": مقدار}

   ب) کنسلی‌ها: هر رزروی که تاریخ ورودش هنوز نگذشته و روی پلتفرم دیگه
      نشونش نمی‌ده یا وضعیتش "cancelled" شده. فقط این دوتا رو لازم داری:
      - property
      - confirmation_code

۴. نتیجه رو با یه درخواست POST مستقیم بفرست (نه فایل محلی؛ کامپیوتر خودت
   نیازی نیست روشن باشه):

   URL:     https://marktresidenz-eisenach.de/wp-json/marktresidenz/v1/incoming
   Method:  POST
   Headers: X-MRV-Write-Key: <کلید نوشتن — جدا داده می‌شه>
            Content-Type: application/json
   Body (JSON):
   {
     "run_date": "YYYY-MM-DD",
     "new_reservations": [ { ...فیلدهای بالا... } ],
     "cancellations": [ { "property": "...", "confirmation_code": "..." } ]
   }

   اگه هیچ رزرو جدید یا کنسلی‌ای نبود، همون‌طور با لیست‌های خالی بفرست (تا
   معلوم بشه اون روز واقعاً چک شده، نه اینکه اصلاً اجرا نشده).

۵. مستقیماً هیچ فایل اکسلی رو باز/ویرایش نکن — فقط همین درخواست POST رو بفرست.
   اعمال‌کردن روی فایل اصلی جدا و بعداً توسط یه اسکریپت دیگه انجام می‌شه.

۶. جواب موفق باید شبیه این باشه: {"ok":true,"id":<عدد>}. اگه جواب دیگه‌ای
   گرفتی (مخصوصاً کد خطای ۴۰۱ یا ۴۰۳)، یعنی کلید اشتباهه — کار رو متوقف کن و
   گزارش بده، حدس نزن.
```

---

## نکات فنی (برای مرجع، نه بخشی از خود فرمان)

- کلید نوشتن (`X-MRV-Write-Key`) فقط اجازه‌ی نوشتن داره، نمی‌تونه چیزی از صف
  بخونه — پس حتی اگه لو بره، بدترین حالت داده مزخرف نوشتن، نه دسترسی به
  اطلاعات مهمان.
- اسکریپت `tools/apply_incoming.py` تصمیم می‌گیره کدوم فیلد کجا می‌ره و کدوم
  فیلد فعلاً دستی/فاز ۳ می‌مونه — Cowork لازم نیست این تصمیم رو بگیره، فقط
  هرچی می‌بینه رو با برچسب درست بفرسته.
- پیاده‌سازی سمت سرور: `wordpress-plugin/marktresidenz-incoming-api.php`
